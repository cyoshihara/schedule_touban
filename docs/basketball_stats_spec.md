## 1. 概要 / 想定ユーザー

少年団・ミニバス〜中学（U12/U15）チームの保護者・コーチ・スコアラーが、**1試合のスコアとボックススコア（選手別スタッツ）を記録・集計**するためのアプリです。既存の「お当番スケジューリングアプリ」と同じ Python + Streamlit + polars スタックで、同一リポジトリ／同一チーム運用への組み込みを前提とします。

想定する主な利用シーン:

- **試合中のリアルタイム記録**（メイン）: ベンチ脇でタブレット／スマホのブラウザから、得点・ファウル・主要スタッツをタップで記録する。
- 試合後の集計閲覧: 試合終了後にボックススコアを確認・共有する。
- シーズン累計の閲覧（将来拡張）: 選手ごとの平均スタッツを振り返る。

想定ユーザー像:

- **スコアラー（記録者）**: 試合中に素早く入力。誤入力の即時取り消し（undo）が最重要。
- **コーチ／保護者（閲覧者）**: 試合後にボックススコアやチーム合計を見る。

技術レベルの前提: 競技規則は **JBA / FIBA ルール準拠**（クォーター制、チームファウル、ボーナススロー等）を基準にしつつ、MVP では細かいルール判定は自動化せず手入力中心とします。

## 3. スコープ（MVP と将来拡張）

### MVP に含む（Must）

- 試合の新規作成（自チーム名・相手チーム名・日付・クォーター数）
- 自チームの出場選手をその試合用に登録（背番号・名前）
- **リアルタイム得点入力**: 選手をタップ → 得点種別（2P 成功/失敗、3P 成功/失敗、FT 成功/失敗）をタップ
- 主要スタッツのタップ入力: リバウンド(O/D)、アシスト、スティール、ブロック、ターンオーバー、ファウル
- **直前操作の取り消し（Undo）**
- スコアボード表示（両チーム合計得点、クォーター別、チームファウル）
- ボックススコア表示（選手別スタッツ＋派生指標、チーム合計）
- 試合データの CSV 保存・読み込み

### MVP に含まない（将来拡張）

- 出場時間の自動計測・オンコート5人管理・自動 +/−
- 相手チームの選手別スタッツ
- シーズン累計／選手別平均ダッシュボード
- Google Drive 同期、複数端末同時編集
- 認証・権限管理
- ショットチャート（コート座標プロット）
- イベントの時系列リプレイ表示

## 5. バスケ統計の定義

曖昧さを残さないため、記録項目と派生指標を明確化します。

### 5.1 記録するスタッツ（生データ＝イベントから集計）

| 略称 | 項目 | 定義 / 入力ルール |
|---|---|---|
| PTS | 得点 | FT成功×1 + FG(2P)成功×2 + 3P成功×3 |
| FGM / FGA | フィールドゴール成功/試投 | 2Pと3Pの合計。FGA = 成功+失敗。**FT は含めない** |
| 2PM / 2PA | 2P成功/試投 | リング近〜ミドルの2点シュート |
| 3PM / 3PA | 3P成功/試投 | 3点ラインより外。3PMは FGM にも算入 |
| FTM / FTA | フリースロー成功/試投 | 1本ごとに成功/失敗を記録 |
| OREB | オフェンスリバウンド | 自チーム攻撃時のリバウンド |
| DREB | ディフェンスリバウンド | 相手攻撃時のリバウンド |
| REB | 総リバウンド | OREB + DREB（派生） |
| AST | アシスト | **得点に直接つながったパス**を出した選手に1。シュート成功イベントに紐付けて任意付与 |
| STL | スティール | 相手のボールを奪った |
| BLK | ブロック | 相手のシュートを阻止した |
| TO | ターンオーバー | 攻撃権を失うミス（トラベリング、パスミス、オフェンスファウル等） |
| PF | パーソナルファウル | 選手の個人ファウル。チームファウルにも算入 |
| MIN | 出場時間 | MVPは任意手入力（自動計測は将来拡張） |

> アシストの運用方針: シュート成功を記録した直後に「アシスト者を選ぶ（任意・スキップ可）」ステップを置くか、独立イベントとして後付けする。MVP では**独立タップ入力**（誰が・スキップ可）で簡潔にします。確認したい点に含めます。

### 5.2 派生指標（集計時に計算）

| 指標 | 計算式 | 備考 |
|---|---|---|
| FG% | FGM / FGA | FGA=0 のとき表示は「-」 |
| 2P% | 2PM / 2PA | 同上 |
| 3P% | 3PM / 3PA | 同上 |
| FT% | FTM / FTA | 同上 |
| eFG% | (FGM + 0.5 × 3PM) / FGA | 実効FG% |
| TS% | PTS / (2 × (FGA + 0.44 × FTA)) | トゥルーシューティング%。分母0は「-」 |
| REB | OREB + DREB | |
| チーム合計 | 各項目の選手合計 | ボックススコア最下行に表示 |
| +/− | （将来拡張） | オンコート管理が前提のためMVP外 |

すべての%は分母0の場合に `null`（表示は「-」）とし、ゼロ除算を避けます。

## 6. データモデル

**方針: イベントソーシング型（A7）**。プレイ1つを `event` として追記し、`boxscore` はイベントから polars で集計する**派生ビュー**とします。これにより Undo＝最終イベント削除で済み、訂正・再集計が単純になります。

### 6.1 エンティティと関係

```
team (1) ──< game >── (1) team          ※自/相手
game (1) ──< player_in_game (出場登録)
game (1) ──< event (プレイ/イベント)
event   ──> player（出場選手）/ quarter（ピリオド）
boxscore = event を player×game で集計した派生テーブル（永続化しない／キャッシュ）
```

### 6.2 スキーマ案（CSV / 将来 SQLite テーブル）

**mst_team.csv**（任意・MVPは試合内に名前直書きでも可）
| col | 型 | 説明 |
|---|---|---|
| team_id | int | チームID |
| team_name | str | チーム名 |

**mst_player.csv**（F13、Could。MVPは game_player に直接登録でも可）
| col | 型 | 説明 |
|---|---|---|
| player_id | int | 選手ID |
| team_id | int | 所属チーム |
| player_name | str | 氏名 |
| number | int | 背番号 |

**trn_game.csv**（試合）
| col | 型 | 説明 |
|---|---|---|
| game_id | int | 試合ID（採番） |
| date | date | 試合日 |
| home_team_name | str | 自チーム名 |
| away_team_name | str | 相手チーム名 |
| num_quarters | int | クォーター数（例:4） |
| quarter_minutes | int | 1Qの分数 |
| status | str | in_progress / finished |
| created_at | datetime | 作成時刻 |

**trn_game_player.csv**（出場選手＝試合×選手）
| col | 型 | 説明 |
|---|---|---|
| game_id | int | |
| player_id | int | 当試合内ローカルIDでも可 |
| player_name | str | |
| number | int | 背番号 |

**trn_event.csv**（イベント＝中核テーブル）
| col | 型 | 説明 |
|---|---|---|
| event_id | int | 連番（Undoは最大event_id削除） |
| game_id | int | |
| quarter | int | 発生クォーター |
| team_side | str | home / away |
| player_id | int | 主体選手（away得点は null 可） |
| event_type | str | 下記の列挙 |
| points | int | 得点イベント時の加点（0/1/2/3） |
| made | bool | シュート系で成功/失敗 |
| assist_player_id | int | 任意（得点に紐付くアシスト者） |
| created_at | datetime | 記録時刻 |

`event_type` の列挙（曖昧さ排除のため固定値）:
`SHOT_2PT`, `SHOT_3PT`, `FREE_THROW`, `REB_OFF`, `REB_DEF`, `ASSIST`, `STEAL`, `BLOCK`, `TURNOVER`, `FOUL`, `AWAY_SCORE`

- シュート系（`SHOT_2PT`/`SHOT_3PT`/`FREE_THROW`）は `made`(成功/失敗) と `points` を持つ。
- 集計（boxscore）はこのイベント表を polars で `group_by(player_id)` 集計し、5章の式で派生指標を算出。

> CSV ではトランザクション・型保証が弱いため、**将来 SQLite へ移行**して整合性と並行アクセスを確保する想定（8章）。

## 7. 画面 / UX 設計

スマホ／タブレット縦持ちでの**片手・素早い入力**を最優先。タップ数を最小化し、Undo を常時表示します。

### 7.1 画面遷移

```
[ホーム / 試合一覧]
   ├─ [新規試合作成] → [出場選手登録] → [記録画面]
   ├─ 既存試合を選択 → [記録画面]（途中再開）
   └─ 既存試合を選択 → [ボックススコア]
[記録画面] ⇄ [ボックススコア]（タブ切替）
```

Streamlit では `st.sidebar` のラジオ or `st.tabs` でページ切替、`st.session_state` に現在の `game_id`・`current_quarter`・直近イベントを保持します。

### 7.2 各画面の要素

**ホーム / 試合一覧**
- 「新規試合」ボタン、過去試合リスト（日付・対戦相手・スコア）、選択して「記録」「ボックススコア」へ。

**新規試合作成**
- 自チーム名、相手チーム名、日付、クォーター数、1Q分数 → 作成。

**出場選手登録**
- `st.data_editor`（`num_rows="dynamic"`、既存 main.py で実績あり）で 背番号・氏名 を行追加入力。

**記録画面（メイン）**
- 上部に**スコアボード**: `Home XX − YY Away`、現在クォーター、Home/Away チームファウル数。
- **選手選択**: 背番号ボタンのグリッド（タップで「選択中選手」をハイライト）。
- **アクションボタン群**（選択中選手に対して）:
  - 得点系: `2P◯` `2P✕` `3P◯` `3P✕` `FT◯` `FT✕`
  - スタッツ系: `OREB` `DREB` `AST` `STL` `BLK` `TO` `FOUL`
- **相手得点**（F10）: `相手 +1 / +2 / +3` ボタン。
- **Undo ボタン**を常時上部固定的に配置（直前イベントの種別を表示し「取り消す」）。
- クォーター切替: `次のQへ` ボタン（チームファウル表示はQ別に集計）。
- 直近イベントログ（最新5件）を簡易表示し、誤りに気づきやすくする。

**ボックススコア画面**
- 自チーム選手別スタッツ表（polars DataFrame を `st.dataframe`）。列: 背番/名前/PTS/FGM-FGA/3PM-3PA/FTM-FTA/OREB/DREB/REB/AST/STL/BLK/TO/PF と %系。
- 最下行にチーム合計。CSVエクスポート（F12）。

### 7.3 入力フローの原則

1. 「選手を選ぶ」→「アクションを押す」の**2タップ**を基本動線にする。
2. シュート成功後のアシスト付与は任意・スキップ可（モーダルにせず独立ボタンで簡潔に）。
3. **Undo は1操作で直前イベントを完全取消**し、スコア・ファウルを再集計。
4. すべての操作後に `st.session_state` と CSV（オートセーブ or 明示保存）を更新。MVP は**操作ごとにイベントCSVへ追記**でデータ消失を防ぐ。

## 8. 技術構成

### 8.1 スタック（既存踏襲）

- Python 3.11（`.devcontainer` の `python:1-3.11-bullseye` に準拠）
- Streamlit 1.41.1（UI）
- polars 1.21.0（集計・派生指標計算）
- 永続化: **MVPは CSV（`./tmp` 配下）**、将来 **SQLite**（`sqlite3` 標準ライブラリ）へ移行
- 既存の `requirements.txt` に新規依存追加は原則不要（pulp / google 系は本機能では未使用）

### 8.2 CSV → SQLite の方針

- MVP は既存アプリと同じく CSV で開始（学習コスト最小・既存 `GoogleDriveService` で同期も流用可）。
- ただしイベントソーシングは追記・整合性・並行性で SQLite が有利。**MVP安定後に SQLite へ移行**。移行時もイベント表中心の構造は不変なので置換が容易。

### 8.3 ディレクトリ構成案（既存 `src/` フラット構成を踏襲）

既存は `src/` 直下にモジュールを置くフラット構成（`main.py`, `const.py`, `utils.py`, `optimize.py`）。これに合わせ、スコアアプリも `src/` 配下にプレフィクス付きモジュールで追加します。

```
src/
  stats_app.py        # Streamlit エントリ（記録/ボックススコアUI）— main.py に倣う
  stats_const.py      # 定数: event_type 列挙, スタッツ定義, デフォルトQ数/時間
  stats_models.py     # CSV/SQLite I/O、game/player/event の読み書き
  stats_logic.py      # polars 集計: boxscore 生成、派生指標(eFG%/TS%等)、undo
tmp/                  # CSV 永続化先（.gitignore 済み）
  trn_game.csv
  trn_game_player.csv
  trn_event.csv
  mst_team.csv / mst_player.csv（任意）
```

## 10. 受け入れ基準（Acceptance Criteria）

evaluator が検証できるテスト可能条件:

1. **試合作成**: 新規試合を作成すると `trn_game.csv` に一意の `game_id` で1行追加され、`status=in_progress` になる。
2. **選手登録**: 背番号・氏名を入力すると `trn_game_player.csv` に当該 game_id の行が追加される。
3. **得点集計**: 選手Aに `2P◯` を1回、`3P◯` を1回記録すると、Aの PTS=5、FGM=2、FGA=2、3PM=1、3PA=1、チーム得点=5 になる。
4. **失敗の反映**: `2P✕` を記録すると FGA が +1（FGM据置）、PTS据置になる。
5. **FT集計**: `FT◯`×2、`FT✕`×1 で FTM=2、FTA=3、PTS=+2。
6. **リバウンドO/D区別**: `OREB` と `DREB` を別カウントし、REB=OREB+DREB が表示される。
7. **派生指標**: 上記から FG%、eFG%、TS% が定義式どおり算出され、分母0の項目は「-」表示になる。
8. **Undo**: 直前の得点イベントを Undo すると、そのイベントが `trn_event.csv` から消え、スコア・選手スタッツが取消前の状態に戻る。
9. **チームファウル**: 選手に `FOUL` を記録するとチームファウルが +1 され、クォーター切替でQ別集計が更新される。
10. **相手得点**: `相手 +2` でアウェイチームスコアが +2 される（自チームスタッツは不変）。
11. **永続化往復**: 記録後にアプリを再読込しても、保存済みイベントからボックススコアとスコアが同一に再現される。
12. **チーム合計**: ボックススコア最下行のチーム合計が各選手スタッツの合計と一致する。
